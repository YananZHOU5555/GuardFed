# Explicit source-version cumulative acceptance

`collect_valid_replay.py` reads SHA-reviewed offserver proofs plus their original archive bytes, verifies every archive member SHA, checks source-version/strict/receipt/prediction/checkpoint/result/rawjob identities and the actual three-view records, and resolves only declared original job/inventory aliases. The unique key is the frozen inventory scientific cell/ID. Distinct checkpoint-content SHA is a disclosure count; equal weight bytes across different scientific cells do not merge those cells or prevent completion.

Current entry is `cumulative_17_accepted.json`, reproduced from `collection_inputs_17.json`. It includes every accepted canonical ID, original job ID, source version and archive/proof/receipt/prediction/model/result/rawjob SHA. The failed original phase4 attempt remains separately referenced with accepted_n0; its eight interrupted/failed IDs are later accepted only through the new v4 attempt. Static900 semantic inspection is not image replay and cannot enter accepted counts. Full completion requires all900 unique frozen IDs with actual native and three-view acceptance; test and new800 mechanism controls remain outside this cohort.

CLI accepts `--inventory PATH --proof v2|v3|v4 PROOF_PATH REVIEWED_SHA256` (repeatable), optional `--failure-proof PATH REVIEWED_SHA256`, and `--output NEW_PATH`. The archive and its member manifest must be restored alongside each proof at their exact accepted bytes; absent Git-excluded archives must be recovered through their published archive/SHA restore chains before recomputing. `check_collect.py` exercised the actual17 collection and six refusal cases. It intentionally preserves its controlled corruptions under `collector_refusal_inputs/`.

Future successful batches append a new proof to a new collection-input JSON and write a new cumulative receipt. Old cumulative receipts and phase seals are not edited. Duplicate canonical IDs across proof inputs are rejected, including alias collisions. Interrupted bulk attempts require separate strict validation and an explicitly reviewed partial-proof adaptation before their completed subset can be reused; this collector currently accepts only fully accepted selected batches. No silent skip/resume or automatic retry is implemented.
