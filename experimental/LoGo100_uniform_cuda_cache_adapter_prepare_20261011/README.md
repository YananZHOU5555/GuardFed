The original bridge is the byte-pinned screen source for the four reused records, or the actually accepted fullcoverage bridge for the other96. Its matching original protocol, reuse manifest, official adapter/upstream and job source identities remain required. The interface imports only stdlib. Scientific modules are supplied by a future real CPU-only runtime; no scientific function is called by preparation/checks.

Root must supply actual approval, new server output path, single-thread CPU ownership and deadline, all seven old artifact roles, and real module/source SHA pins. Old post_state, mapping and job hashes are in `EXACT100.json`, extracted from existing root-accepted metadata without opening F. No original evidence is overwritten or relabeled. New output retains the legacy checker-required evidence_stage string but has a separate formal_binding identifying frozen-model reevaluation and adopted CUDA cache provenance.

The currently absent, reviewed `cache_verifier` module must implement:

- `verify_root_index(root_pin,index_pin,ordered_FedAvg_ids)` → root_adopted true only after real verification, exact root/index SHA, and ordered100 records. Each record needs id, original inventory_record and member pins `receipt`, `predictions`, `formal_binding`, `saved_acceptance`, `original_result`.
- `load_cache(record)` → root/valid margins plus root_y, valid_y, root_sensitive and valid_sensitive derived from the original bound metadata/root reconstruction. It must not evaluate a CNN, refit, read test labels or substitute historical CPU margins.

These methods and their real root/index schema have not been implemented or approved here. The API validates the callback's actual source path/SHA, complete100 order, original FedAvg checkpoint/job/result identity, CUDA receipt, saved member hashes and root/valid ID order; root must independently review the callback's label and adoption proof logic before authorization. Full/GuardFed caches and server-only ACCEPTED markers are not valid substitutes.

`resource_gate(approval)` is likewise a real reviewed callback. New caches are reused; the CNN is never evaluated again. The postprocessor remains CPU, netcal1.3.6; old fitted state is applied without any `fit_predict` or `save_post` call. Historical cross-route metric differences are retained and are not an invented equality gate.

Run `prepare_source.py` and `check_source.py` only for local source/JSON verification. No SSH/F/Git/STATE/arrays/Torch or scientific execution occurred. Actual root cache, callback source, file restoration and runtime approval remain null; runtime_ready is false.
