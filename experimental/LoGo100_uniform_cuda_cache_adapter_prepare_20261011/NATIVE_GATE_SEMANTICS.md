# Exact source meaning and authorization boundary

The accepted LoGo100 native figures come from the saved CPU postprocessing route: accepted FedAvg margins → CPU float32 sigmoid → recipe07 official LoGoFair-DP / netcal1.3.6 → saved post_state → predictions. The pretrained FedAvg CNN used GPU training; that does not make the old LoGo postcache a GPU evaluation. Existing accepted records report Torch2.8.0+cpu for this postprocessing stage.

The original `checked_output` checks the complete artifact/job/mapping identity, restores the saved post_state, predicts again on the same saved score cache, requires prediction vectors to match exactly, and checks all three recomputed metrics against that output's own `result.json` within1e-12. It does **not** compare a new route's metrics with a historical LoGo result. This source preserves that predicate and every scientific statement of the checker. Only its reuse-manifest lookup is privately bound to the already root-adopted FedAvg CUDA cache identity.

`load_post` restores fitted netcal calibrators, client thresholds, global lambda, settings and history. Calling its predictor on new FedAvg CUDA margins is a frozen-model reevaluation. It needs no `fit_predict`, no optimizer, no new recipe selection and no additional CNN. The adapter copies the old accepted post_state bytes to the new output and checks the SHA remains exact. Original float32 CPU sigmoid, netcal1.3.6, recipe07 and fixed20 declared virtual populations remain; those populations are not actual training-client IDs.

`fit_predict` would instead seed1719, instantiate a new postprocessor and run the official root-label optimization and beta MLE again. Same recipe and seed would still produce a newly fitted derived model. This interface does not expose that path; whether to authorize it requires an explicit scope decision. Author decisionB approves complete uniform CUDA reevaluation, not silent postprocessor retraining, changed native semantics, a new primary endpoint or test evaluation.

Historical CPU metrics are retained verbatim. Their differences from the newly evaluated frozen classifier are reported as cross-route diagnostics and do not by themselves fail acceptance. Nonzero differences must not be described as equivalent or as automatic native0diff. Original saved-prediction/hash/metric-consistency failures still fail closed, preserve output and prohibit retry. Numerical mismatches require evidence and diagnosis; no tolerance is relaxed.

The early cache catalogue has90 null `current_mapping_sha256` fields. Those nulls remain untouched. Later root-accepted records100 and ACCEPTANCE100 provide all100 actual mapping hashes and post/job artifact identities. The preparation indexes those later pins explicitly; no mapping bytes, population IDs or missing hashes were generated. Actual restored files are still missing from this interface's runtime binding.

No new FedAvg CUDA100 root adoption/index currently exists for this adapter. A server `formal_saved_acceptance.json` is not an offserver/root adoption. The future cache verifier must be source-reviewed and hash-bound, verify the real adopted100 index and original metadata/root labels, and load one existing cache without forward/fit. Its actual source/schema is a named missing dependency, not a fabricated success result.
