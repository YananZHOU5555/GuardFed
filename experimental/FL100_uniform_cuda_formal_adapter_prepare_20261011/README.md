`args.repo`, `args.torch_module`, `args.pandas_module` are real root-bootstrapped Linux objects. `candidate` is the exact original package for the selected row; this adapter does not run candidate.run, its old CPU authorization, or its CPU scheduling gate. It invokes the original package/source/manifest gates and the same `bound_bridge(...runtime=True)` → `identity_record` sequence used by `original_fl_identity`. All seven original candidate/manifest registries remain distinct, including original screen CRLF/LF job checks and the earliest package's `originals/PROOF_PINS.json` location.

The selected `runtime_dependencies` must contain exactly candidate, manifest, package_seal, core, cnn, replay, evaluator, bridge, source_reuse, proof_registry and saved_science. Paths are not inferred from local Windows paths. Original candidate packages still require their complete original dependencies; this small preparation does not claim those dependencies are newly deployed.

Forward reuses the actual500 GPU body a00d8d… with only the original FL identity/path call adaptation and receipt labels. `SOURCE_ADAPTATIONS.json` gives an exact inverse. No CNN, model config, seed, threshold fitter, tie rule, scoring function or1e-12 comparison changes. The evaluator and metadata reconstruction remain the original private bridge science.

Saved acceptance executes the entire original Linux `check_saved` d512e5… unchanged, in its original v2/mapping/full_hashes/mapped_functions/KINDS context. It checks actual CUDA receipt/runtime and fixed source/artifact identity, reconstructs root and checks original cached-root fitting, predictions, metrics and native tolerance; it performs no additional CNN. Root acceptance, transport and independent saved-output audit remain separate. The previous Windows exact-refit failure remains failed, and historical CPU tables are not CUDA tables.

`prepare_source.py` and `check_source.py` perform only local source/JSON operations. They do not import Torch/NumPy/pandas, read arrays, use F/SSH/Git, or evaluate science. Metadata positive fixtures are synthetic in memory, not approvals. No runtime-ready claim: actual Linux dependencies, resource/source preflight, GPU UUID/CPU allowance, deadline, author/cohort/source seal locations, formal output namespace and root authorization remain unbound. No queue is started.

Runtime is one record per explicit API call. Existing output or failure refuses replay; failure evidence is retained; no retry, test, training, old CPU reuse or diagnostic promotion is allowed. This supplies a formal interface, not completion of100, all17 methods or a final primary endpoint.
